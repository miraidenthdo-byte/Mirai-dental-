## 3. アプリの機能（概要）

- パステルピンクのやさしいデザイン。カテゴリ：受付・会計／診療補助／衛生士業務／滅菌・消毒／緊急時対応／開院・閉院／患者さま対応／器具・材料／カルテ・用語／院内ルール・申請
- マニュアルはステップ形式（見出し・本文・声かけ例・コツ・注意・画像・動画・リンク）
- その場で編集：**編集ロック**を外してから編集（管理者が4桁の暗証番号を設定可）
- スタッフは**6桁のログインコード**でログイン。進み具合（どこまで読んだか）を記録し、管理者が「スタッフ別」「マニュアル別」で確認
- 退職者対策：管理者ページで「利用を停止」すると即ログアウト。コード再発行、全員ログアウト、端末一覧
- 画像・動画：アプリから追加でき、Google ドライブの非公開フォルダに保存。ログイン中の人だけがアプリ経由で見られる
- Slack通知：マニュアルの追加・更新・削除をチャンネルに送る（管理者ページ「スタッフ管理」→「Slack通知」で Webhook URL を登録）
- Apps Script が無い環境（ファイルを直接開いた場合）は「体験モード」で動き、データはブラウザ内に保存される

## 4. 必ず守ること（ハマりどころ）

1. **`<script>` の中に `/*` や `*/` を書かない。**
   Apps Script（HtmlService）は配信時に `/* … */` をコメントとみなして削除する。文字列やテンプレートの中でも削除されるため、`accept="image/*"` と書いただけで約100行が消えて画面が壊れた。
   コメントは `//` を使う。どうしても必要な文字は `'image/' + '*'` のように分けて組み立てる。
2. **index.html を直したら `python3 data/fix-diag.py index.html` を実行する。**
   上の禁止文字のチェックと、読み込みエラー時に「何行目から崩れているか」を表示する診断情報（正しい長さ・行数・行ごとのハッシュ）を更新する。実行しないと、エラー時の診断が誤った場所を指す。
3. **パスワード類について**：Notion から取り込んだマニュアルには、院内PCのログイン番号やクレジット端末・iTero のIDとパスワードがそのまま入っている（ユーザーの希望でアプリ内に残している）。リポジトリ外へ公開するプレビュー等を作るときは必ず伏せること。
4. **ユーザーに渡すファイル**は `.txt` にする（Mac のテキストエディットで .html を開くと表示が崩れるため）。ユーザーはそれを開いて全選択・コピーし、Apps Script に貼り付ける。
5. スマホでは **iPhone は Safari、Android は Chrome** で開いてもらう。LINE 内のブラウザや、Google アカウントが複数入った Chrome では「現在、ファイルを開くことができません」になることがある。
6. コミットメッセージやファイルに AI のモデル名を書かない。
